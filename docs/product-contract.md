# MVP 제품 계약

## 왜 만드는가

검색과 AI로 찾지 못한 답도 인간의 경험·관찰·판단을 통해 드러나고 다음 사람에게 남아야 한다.
직접 경험을 쓰는 경로와 질문에 답하는 경로를 동등하게 제공한다.
답설로 널리 전하는 시의 '뒤에 오는 사람에게 남는 길'을 출처·기여·결과의 기록으로 구현한다.

## 첫 성공 장면

1. A가 검색/AI로 해결되지 않은 질문을 공개 또는 그룹 안에 게시한다.
2. B가 자신의 이름으로 조건·근거를 포함한 답변을 남긴다.
3. A가 도움된 답을 선택하고 별도로 실제 적용 결과를 남긴다.
4. C가 검색으로 답을 찾아 재사용 목적을 기록하거나 원천 버전을 연결해 이어 묻는다.
5. C의 정정을 B가 반영하면 새 답 버전에 C의 기여가 표시된다.
6. 기존 선택은 이전 버전에 남고, 이를 참고했던 파생 답에는 재검토 필요가 전파된다.

질문자가 모든 후속 기여를 승인할 독점 권한을 갖지 않는다. 답변 수정은 작성자만 가능하고 누구나 다른 답·정정 제안을 남길 수 있다.

## 지켜야 하는 구분

저장 ≠ 질문자의 선택 ≠ 실제 적용 ≠ 독립 검증 ≠ 공개 ≠ 투자.
개별 적용 결과는 관찰자의 보고이며 인과 관계의 확정이나 보편적 효능을 의미하지 않는다.
미해결, 실패, 부분 도움도 정상적인 기록이다. AI 출력으로 해결 여부를 자동 변경하지 않는다.

## 범위와 권한

`public`, `personal:<user>`, `group:<space>`를 같은 질문/답변 모델에 적용한다.
조회·검색·기여·출처·저장·AI 대화·투자에 서버 정책을 적용한다.
그룹을 떠나면 작성자라도 그룹 자료에 접근할 수 없다. 기존 기여는 그룹에 보존된다.
당사자의 투자 원금 회수는 허용하되 탈퇴한 그룹의 제목·내용은 개인 화면에서 숨긴다.
공개 자료를 그룹 안에서 참고할 수 있다. 그룹·개인 자료를 더 넓은 공간에 출처로 연결할 수 없다.
공개 범위 변경은 제공하지 않는다. 공개할 새 글을 사람이 직접 검토해서 작성해야 한다.

## 인정과 투자

인정의 근거는 실제 작성자, 반영한 보강자, 적용 보고자, 재사용자다.
한 사람의 여러 기록을 새로운 독립 참여자로 중복 계산하지 않는다. 본인의 자기 적용/재사용은 인정 수에서 제외한다.
포인트 잔액과 인정은 별개다. 계정 생성 포인트의 남용 방지와 실재 사용자 검증은 아직 정산 수준에 도달하지 않았다.
따라서 포인트는 실험으로만 운영하며 현금 가치와 배당을 제공하지 않는다.
작성자가 해당 버전에 먼저 예치하면 다른 사람도 참여할 수 있다. 작성자도 원금을 회수할 수 있으며 그 뒤 새 참여는 다시 선투자 조건을 확인한다.
새 버전은 새 투자 대상이다. 지난 투자 내역과 원금은 이전 버전에 남는다.

현상금/답변 의뢰와 지식 투자는 추후 별도 계약·원장으로 구현한다. 기여자·투자자 공동 보상은 재원과 이의 절차를 검증한 뒤 운영한다.
60/30/10 등 논의된 배분 수치는 확정 규칙이 아니므로 코드에 자동 정산으로 넣지 않았다.

## 단순한 구현의 기준

서버 렌더링, 기본 HTML 폼·날짜 입력, SQLite 트랜잭션과 검증된 OAuth 라이브러리를 사용한다.
완전한 지식 그래프 편집기, 별도 상태관리 프레임워크, 자율 에이전트 체계를 첫 버전에 추가하지 않는다.
사용 장면을 먼저 정하고 배포된 서비스에서 확인하는 개발 방식을 적용한다.
Context Mode/Ponytail/JetBrains에 대한 사용자 제안은 평가 대상으로 기록했으며 자동 설치하거나 현재 적용 중이라고 주장하지 않는다.
